# 05 · RAG 检索增强（demo12）

> 前置：Demo06/07（插件与工具调用）｜涉及 Demo：demo12
> 目标：理解 RAG 三段式（索引/检索/生成），看懂余弦相似度检索内核，掌握防幻觉的工程做法。

## 1. 为什么需要 RAG

大模型有两个天然边界：**知识截止**（训练之后的事不知道）和**私有知识**（你店的会员规则它没学过）。
RAG（Retrieval-Augmented Generation）的思路：回答前先从知识库检索相关内容，拼进上下文再生成——
把"记住知识"变成"按需查资料"。

## 2. 三段式架构

```
┌─────────┐   embed   ┌──────────────┐
│ 文档集   │ ────────► │ 向量库(内存)   │   ← ① 索引 Indexing（离线/可重复）
└─────────┘           └──────────────┘
                              ▲
                              │ 余弦相似度 TopK
┌─────────┐   embed   ┌──────┴───────┐
│ 用户问题  │ ────────► │ 检索 Retrieval │   ← ② 检索
└─────────┘           └──────────────┘
                              │ 上下文
                              ▼
                       ┌──────────────┐
                       │ ChatCompletion │   ← ③ 生成 Generation（带引用）
                       └──────────────┘
```

## 3. 检索内核：余弦相似度（demo12 的教学核心）

RAG 听起来神秘，内核就是六十行数学：

```
相似度 = (A·B) / (|A| × |B|)
```

- 取值 [-1, 1]，1 = 方向完全一致
- 选**余弦**而不是欧氏距离：文本向量的模长携带"篇幅"信息，而我们要的是语义方向
- 取 TopK：按相似度降序取前 K 条，K 是"上下文预算与召回率"的权衡

demo12 的 `InMemoryVectorStore` 把这个内核单独成类——**不依赖任何外部服务，可离线单测**。
SK 的 `VectorStore` 抽象是同一件事的工程化版（异步集合、记录映射、多后端），理解内核后再看抽象会清晰很多。

## 4. 防幻觉：RAG 最重要的产品决策

demo12 的三条防线：

| 防线 | 做法 |
|---|---|
| 检索不到就明说 | 索引为空时返回引导信息，不让模型硬答 |
| 系统提示约束 | "只能使用知识库中的信息，禁止编造；未提及就回答未提及" |
| 强制带引用 | 回答末尾标注【依据文档N】，用户可验证出处 |

第三条最容易被忽略但价值最大：**可验证的答案**比"听起来对"的答案更有用，
也是客服、法务等场景敢用 AI 的前提。

## 5. 与 Spring AI 版 RAG 的对照

本项目是 Semantic Kernel 教学，`spring-ai-teaching-demo` 的 demo08 是 Spring AI 版 RAG。两者差异**只在 SDK 调用方式**：

| 环节 | Semantic Kernel | Spring AI |
|---|---|---|
| 索引 | `generateEmbeddingsAsync` + 自存 | `EmbeddingModel.embed()` + VectorStore |
| 检索 | 余弦相似度手写 | `vectorStore.similaritySearch()` |
| 生成 | `getChatMessageContentsAsync` | `chatClient.prompt()` |

**思想（索引/检索/生成）是框架无关的**——这是"学会一个，看懂一片"的原因。

## 6. 测试策略：假 embedding 服务

RAG 全链路测试通常需要真实 embedding API。demo12 的做法：

1. `RagService` 依赖 `TextEmbeddingGenerationService` **接口**（不是 OpenAI 实现类）
2. 测试用 `FakeEmbeddingService`：词袋模型——每个维度对应一个关键词，计数即向量值
3. 于是"配送费多少钱"的查询向量必然与配送文档最相似，**检索结果可预期、可断言**

14 个单测覆盖：余弦数学（同向/正交/反向/零向量/维度不一致）、TopK 排序、
索引幂等、空库行为、异常传播。**不需要 API Key，不需要网络。**

> 两个测试细节值得记住：
> ① 浮点断言要用 `isCloseTo(x, within(1e-9))`——`sqrt` 后 -5/5 可能是 -0.9999999999999998；
> ② 异常传播用例要用 `indexDocuments` 触发——空库时 `retrieve` 会短路返回，根本调不到 embedding。

## 7. 生产化路径

| 教学实现 | 生产替换 |
|---|---|
| 整篇文档索引 | 文档加载 + 切分（chunking）+ 重叠窗口 |
| 内存向量库 | Milvus / Qdrant / PgVector |
| 词袋/真实 embedding 混合 | 统一 embedding 模型（索引与查询必须同模型，否则维度不一致直接报错） |
| TopK 固定 | 相似度阈值过滤 + 重排（rerank） |
| 单轮问答 | 多轮改写（query rewrite）+ 混合检索（关键词+向量） |
